# 产品原型说明

> AI 智能项目协作平台 | 阶段：Stage 2 (DEV-4) | 日期：2026-10-14
> 原型文件：`index.html`（单文件、零依赖、浏览器直接打开，支持交互演示）

## 一、页面清单

| # | 页面 | 覆盖的 MVP 功能 | 原型中的演示点 |
|---|---|---|---|
| P1 | 项目看板 | M1 看板 / D2 状态驱动 | 四列状态看板、卡片可拖拽、Agent 卡片带执行进度条与成本标签（D5）、wakeup 条件徽标（N1） |
| P2 | Issue 详情 + AI 拆分 | M3 / D4 | 「AI 拆分」模拟流式生成子任务树草稿 → 人工编辑 → 确认入库；状态机按钮（Agent 最高到 in_review，`done` 仅人类可见） |
| P3 | AI 助手面板 | M3 / N2 / N3 | 自然语言建任务输入框、进度洞察摘要（引用 issue 编号）、成本归集面板 |
| P4 | 系统集成设置 | M4 / DEV-7~9 预留 | GitHub 仓库绑定卡片、webhook 状态、Slack/飞书/内部系统的「即将推出」占位 |

左侧导航切换四个页面；右上角「桌面 / 手机」按钮切换视口预览移动端形态。

## 二、核心交互流程（对应验收主线）

### 流程 1：创建任务 → AI 拆分 → 智能分配 → 进度追踪

```
[AI 助手面板] 输入一句话需求
      ↓ 生成结构化任务草稿（标题/优先级/截止日期自动识别）
[看板] 新卡片落入「待办」列
      ↓ 打开卡片 → 点击「AI 拆分」
[Issue 详情] 子任务树以草稿形式流式出现，可编辑/删除/调整顺序
      ↓ 点击「确认拆分」
[看板] 子任务按 stage 出现
      ↓ 点击「智能分配」→ 推荐 assignee（人 or Agent，附理由）
[看板] Agent 卡片显示实时进度条与 token 成本
      ↓ Agent 交付 → 状态自动到「待验收」（in_review）
[Issue 详情] 人类点击「验收完成」（仅人类可见的按钮）→ done
```

### 流程 2：GitHub 状态联动（D2）

```
PR merged (GitHub) → webhook → 看板卡片自动从「进行中」移到「待验收」
卡片上 PR 徽标实时反映 open/merged/closed + checks 状态
```

原型中用卡片 `ACP-14` 上的 PR 徽标与「自动流转」提示演示该链路。

### 流程 3：wakeup 条件唤醒（N1，差异化 D3）

卡片与详情页展示 `⏰ 当 PR checks 通过时唤醒` 条件徽标；设置入口在 Issue 详情「唤醒规则」区。

## 三、设计原则（来自 DEV-3 差异化结论）

| 差异化点 | 原型体现 |
|---|---|
| D1 Agent 一等 assignee | 头像区人/Agent 并列；Agent 卡片有「执行中」呼吸灯；`done` 按钮仅对人类渲染 |
| D2 状态由产出驱动 | 卡片上 PR/checks 徽标；自动流转动画提示 |
| D3 wakeup 异步编排 | 条件徽标 + 详情页唤醒规则区 |
| D4 AI 拆分 + 分阶段 | 拆分抽屉内子任务带 stage 分组标签 |
| D5 成本透明 | 卡片与详情页均展示 `· 12.4k tok · $0.18` 式成本标签 |

## 四、移动端适配方案

**决策（待评审确认）**：MVP 采用**响应式 Web + PWA**，不做原生 App 壳。

| 场景 | 适配策略 |
|---|---|
| 布局 | <768px：侧边栏折叠为底部 Tab（看板/助手/我的）；看板四列改为横向滑动 snap 滚动 |
| 看板拖拽 | 触屏长按 300ms 进入拖拽态（dnd-kit 触摸传感器），短按打开详情 |
| AI 助手 | 移动端全屏抽屉，输入框固定底部，流式输出气泡 |
| 通知 | PWA Push（Stage 4 集成通讯工具前的主通知通道） |
| 性能预算 | 首屏 < 150KB JS（看板页代码分割），LCP < 2.5s（4G） |

原型右上角切换到「手机」视口可预览响应式形态。
